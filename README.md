# Proximity Archipelago

Стратегия о колонии муравьёв. Три запроса требуют ресурсы со склада; выполнение добавляет время и редкую награду. Отказ стоит ресурсов и не даёт награды. Пять закрытых запросов развивают колонию. Стартовый таймер — 3 минуты, население — 5 муравьёв. [Правила эксперимента](docs/TASK_EXPERIMENT.md).

## Запуск и редактирование

Откройте `project.godot` в Godot 4.7.2 и нажмите F5. После обновления завершите прежний запущенный экземпляр игры.

**Дизайнеру:** Project → Tools → «Открыть инструменты уровня». Вкладка **«Уровень»** содержит кнопки карты, каталога цен, начальных ресурсов, заданий и проверки. Нажмите **«1. Открыть карту и рисовать»**: откроется сохранённый уровень и палитра TileMap. Рисуйте кистью, сохраняйте Ctrl+S. Запуск не перерисовывает карту. [Пошаговая инструкция](docs/DESIGNER_WORKFLOW.md).

В главном меню откройте **Карты**. Выберите покрытие или объект в нижней палитре. Для переноса выберите объект, затем клетку назначения. ПКМ стирает объект или покрытие, СКМ двигает камеру. Введите имя и нажмите **Сохранить**. Сохранённые карты доступны в списке; **Играть** проверяет карту и запускает матч. Файлы карт хранятся в `user://maps`.

Карта по умолчанию 50×50. Можно рисовать дальше: границы мира и камеры следуют нарисованным клеткам. Вода не создаёт навигационных узлов; поле расстояний охватывает связанный остров. [Устройство навигации и ограничения](docs/ISLAND_NAVIGATION.md).

## Управление

| Действие | Управление |
| --- | --- |
| Камера | Зажатая ЛКМ, СКМ, стрелки или WASD |
| Пауза и стройка | Пробел, B или «Пауза / стройка» |
| Рисование плана | Инструмент в палитре и ЛКМ |
| Применение плана | ▶, Пробел, Esc или B |
| Отмена в плане | ПКМ снимает последнее добавление на клетке; Ctrl+Z отменяет мазок; X отменяет план |
| Снос | Инструмент «Снос» в палитре |
| Камера в стройке | «Перемещение» и ЛКМ либо СКМ/стрелки/WASD |
| Масштаб карты | Колесо, включая стройку; в обычной игре также − / + |
| Навигационные числа | N: вход в клетку в мс, приоритеты в секундах, выключено |
| Начало расчёта | ПКМ по клетке в режиме приоритетов |
| Данные предприятия | Наведите курсор в режиме чисел |
| Меню, настройки, рестарт | Esc или «…» |
| Масштаб интерфейса | Настройки: 50%, 75%, 100%; исходно 75% |

Строительство по ПКМ удалено. Вне стройки ПКМ ничего не строит. Пища в HUD показана как `всего(свободно)`; стройка и задания не расходуют зарезервированные порции. Снос дома требует подтверждения и уничтожает его жителей. Проверка плана защищает безопасный путь к пище.

Предприятия выбираются по `время пути + 0.5 × (работают + идут)`. Запас продукции не участвует. Красные числа обозначают работу, синие — дома, зелёные — пищу, серые — обычные клетки. На предприятии отображается итоговая оценка с текущей нагрузкой. Боковая карточка показывает `2+1/4` и расчёт.

Дом стоит **10 дерева + 20 камня**. Цены и правила меняются в каталоге; сохранённые изменения подхватываются во время партии. Правило роста ×1.2 можно подключить в Price Rules. [Конфиги, новые ресурсы и рецепты](docs/DESIGNER_WORKFLOW.md).

## Доставка и строительство

Применение плана создаёт стройплощадки. Материалы оплачиваются и закрепляются за заказом на тех базах, где лежали. Носильщики и рабочие перевозят их в пределах своей грузоподъёмности. После полной доставки рабочий собирает постройку; длительность задаёт `BuildOption.construction_seconds` (по умолчанию 4 секунды). До завершения дом не создаёт жителей, улучшение не добавляет мест, дорога не ускоряет движение. Любая покупка с ненулевой ценой в коронах вводится в строй сразу.

Наведите курсор или выберите стройку: карточка показывает доставленные материалы и процент сборки. Снос отменяет заказ. Не забранные со склада материалы возвращаются в доступные запасы, груз в пути муравей относит обратно, уже доставленные материалы теряются. Гибель доставщика уничтожает его груз; стройка покупает замену при наличии ресурсов. Голод продолжает действовать во время доставки и сборки. Новые заявки учитываются в правилах роста цены, а событие завершения постройки происходит только после сборки.

Карты из редактора начинают с готовыми объектами. Экспорт `World.ant_construction` позволяет отдельно проверять прежний мгновенный режим. `tools/check_build_delivery_ui.sh` записывает реальную доставку и сборку в двух разрешениях; старые сценарии палитры и назначения изолируют мгновенные транзакции.

## Муравейники, источники и улучшения добычи

Базовый муравейник строится за одну корону (`game/building/options/base_nest.tres`). Он начинает с четырьмя рабочими и одним носильщиком, вмещает до двадцати жителей и хранит неограниченное количество ресурсов. Казарма вмещает пять жителей, имеет общий склад на сто единиц и отличается оттенком. Носильщики забирают доступный груз из казарм и доставляют в ближайший достижимый базовый муравейник. Запасы баз учитываются вместе при оплате строительства; окно каждой базы показывает её собственный склад.

В редакторе карт выберите «Перенести объект», нажмите на источник и задайте конечность и запас в верхней панели. Эти параметры сохраняются в файле карты. В Godot те же настройки находятся у `Workplace`: `finite_supply` и `remaining_supply`. Старые карты сохраняют бесконечные источники. Конечный источник выдаёт остаток последней партией и прекращает добычу, не удаляя ожидающий доставки груз. Его изображение исчезает при нулевом запасе; построенное улучшение остаётся видимым до сноса.

Лесопилка, каменоломня и ферма добавляют по два рабочих места источникам древесины, камня и пищи соответственно. Они ставятся поверх подходящего источника; снос сначала убирает улучшение, сохраняя источник и его остаток. Цены, ресурс, прибавка мест и иконки заданы в `game/building/options/sawmill.tres`, `quarry.tres` и `farm.tres`. Иконки имеют размер 16×16.

Список `TaskSpec.unlocks` задаёт постройки, которые открывает выполнение задания. Отказ от задания их не открывает. Текущие награды настроены в `game/tasks/default_deck.tres`; открываемая постройка видна в карточке задания.

## Авторская карта «Осколки прилива»

Откройте «Карты», выберите «Осколки прилива», нажмите «Загрузить» и «Играть». Карта поставляется с игрой; её можно редактировать и сохранить собственной копией. Размер — 136×84 клетки. Общий обзор доступен на зуме 0.25×.

Центральная бухта даёт безопасный старт, но ближайшие древесина и камень конечны. Каменный север, лесной запад, плодородный восток и южные отмели соединены узкими перешейками. Дороги ускоряют доставку, казармы размещают рабочих возле источников, а новые базы сокращают рейсы носильщиков. Отдельно лежат остров с лагуной, северо-западный серп, восточный карьер и несколько малых островов. Северо-западу и восточному карьеру нужна собственная столовая перед постоянным заселением.

Карта хранится в `game/worlds/maps/tidal_shards.tres` как нарисованные клетки и объекты; генерации при запуске нет. `bash tools/check_map_ui.sh` записывает обычное по скорости прохождение начала партии без добавления ресурсов. Проверка механик также сравнивает четыре минуты игры с дорогами и лагерями и без строительства.

Проверки выполняются в отдельных копиях проекта. GUI требует X11, OpenGL и ffmpeg. Снимки, видео и отчёты сохраняются **вне репозитория**, по умолчанию в `/tmp/colony-validation`. Другой путь задаётся `COLONY_OUTPUT_ROOT=/absolute/path`.

`World.diagnostics_enabled` включает журнал колонии. [разбор удалённого кода](docs/ISLAND_NAVIGATION.md#очистка).

## Примечания оболочки

1. `get_tree().create_timer(t)` defaults to `process_always = true`. It keeps firing while paused. If you use it in gameplay code, pass false explicitly:
```gdscript
await get_tree().create_timer(0.3, false).timeout
```

2. `get_tree().create_tween()` ignores pause. Always use `node.create_tween()`, because the tween inherits the node's process mode

3. Autoloads inherit pausability from root. If your future `AudioManager` fades music with a tween, set `process_mode = PROCESS_MODE_ALWAYS` in its `_ready()`

4. `await` in `_ready()` works but makes `_ready` `async`. `Router.goto` awaits the fade, so `Boot._ready` returns before the first screen is visible

5. Payload must be set before `add_child`. If you move the `_current.payload = payload` line after `add_child`, `_ready()` in the screen won't see it

6. Hidden menus still receive input unless you guard for it. That's why `MenuBase._unhandled_input` starts with `if not visible: return`

7. `process_mode` is set in the Inspector, not the script, for the shell layers. If you set it in code, make sure it runs before anything can pause - `_enter_tree()` is safe, `_ready()` is too late for the very first frame in edge cases
