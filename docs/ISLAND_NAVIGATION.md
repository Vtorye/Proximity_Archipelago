# Островная навигация и очистка

## Хранение и поиск

TileGrid хранит только проходимые клетки: компактные ID, цену входа, четыре соседних ID и номер связной компоненты. Вода, пустота и блокирующие постройки не создают узлов. Rect2i задаёт геометрические границы для строительства и камеры, но массивы размером с этот прямоугольник не выделяются.

Компоненты собраны в непрерывные диапазоны общего индекса. NavigationField делит этот индекс с неизменяемым снимком, выделяя расстояние float32 и байт направления родителя только для компонент, содержащих источники. Один источник на острове не выделяет расстояния для остальных островов. Мульти-источниковое поле еды охватывает только компоненты со столовыми. Пустой источник даёт пустое поле, стоимость недостижимой клетки — INF.

A* использует AStar2D с точками суши вместо плотного AStarGrid2D. Запрос между разными компонентами отклоняется до поиска. Dijkstra сохраняет цену входа в конечную клетку, включая обратные поля. При загрузке уровня для каждого проходимого рабочего входа строится поле расстояний до него. При назначении клетка муравья переводится в ID узла один раз. Планировщик читает расстояния из полей предприятий своего острова, проверяет слоты и запас сытости и прибавляет текущую нагрузку. Маршрут берётся из того же поля, по которому выбрали вход.

После изменения проходимости или покрытия снимок графа пересобирается за O(L), где L — число проходимых клеток; компоненты тоже пересчитываются. Это корректно объединяет и разделяет острова. Стоимость подготовки графа и его общего индекса не входит в размер массивов поля. Динамической связности с локальным обновлением ещё нет. Несколько соединённых островов после моста образуют одну компоненту: поле охватит всю её сушу. При изменении графа рабочие поля пересчитываются один раз для группы правок. Если меняется только список предприятий, готовые поля действующих входов сохраняются. Память рабочих полей составляет 5 байт на проходимую клетку острова для каждого уникального рабочего входа на нём, без учёта общего графа и служебных данных.

Кэши исходящих полей для ручной диагностики и обратных полей для возвращения домой ограничены восемью записями каждый. Рисование чисел и включённой сетки проходит только по видимому прямоугольнику клеток, а не по всей нарисованной карте. Навигационный слой рисуется непрерывно под HUD: панели интерфейса не вырезают клетки и не меняют область расчёта. В режиме приоритетов ПКМ задаёт исходную клетку, а ЛКМ и стрелки перемещают камеру. Числа рабочих точек содержат штраф 0.5 за работающих и идущих; носильщики домой не входят. Цвет не означает допустимость назначения: голод, путь домой, еда и свободные места проверяются отдельно.

## Проверки

В `tests/island_regressions.gd` два острова по 32×32 разделены миллионом клеток по обеим осям. Геометрический прямоугольник содержит больше триллиона позиций, но граф имеет 2048 узлов, а одиночное поле — 1024 расстояния и родителя, всего 5120 байт этих двух массивов. Сам индекс графа и A* занимают дополнительную память пропорционально суше.

Проверяются отсутствие поиска между островами, несколько источников еды, пустое поле от воды, открытие и закрытие моста, неизменность старого снимка, цена входа и обновление списка доступных предприятий. Нагрузочный тест проверяет тысячу назначений с разных клеток. После подготовки полей ни один из этих запросов не запускает поиск.

## Очистка

Удалены исполняемое меню строительства по ПКМ, его сцена, регистрация в Manifest, BuildMenuContext и ветви ввода/состояния в Match. Проверки переведены на единственную палитру строительства и карточку навигации. Удалены неиспользуемые World.CELL_SIZE, TileGrid.size и дублирующие методы покупки еды у Canteen; питание остаётся в TripPlanner и WorldInventory с резервами.

Проверены ссылки сцен, скриптов, сигналов и тестов. `human.gd` оставлен: на него ссылается действующая сцена муравья. A* и Dijkstra оставлены: первый используется RouteService, оба проверяются независимыми регрессиями. Пустые методы жизненного цикла Workplace — вызываемые точки расширения для переработчиков, а не забытый код. DebugProbe вызывается диагностическим режимом World.

Проверочные скрипты записывают артефакты в COLONY_OUTPUT_ROOT, по умолчанию /tmp/colony-validation. История Git не переписывалась. Исходный ARCHITECTURE_AUDIT.md остаётся архивом прежнего кода, его строки не являются описанием текущего API.
